### 2. Сравнение LLM-моделей

| Критерий | **Локальные (HuggingFace)** <br> *Пример: Mistral 7B, Llama 3 8B* | **Облачные (OpenAI)** <br> *Пример: GPT-4o, GPT-3.5* | **Облачные (YandexGPT)** |
| :--- | :--- | :--- | :--- |
| **Качество ответов** | Среднее/Высокое (зависит от квантования). Для тех. документации — хорошо. | **Отличное**. Лучшее понимание контекста, стиль. | Хорошее для русского языка, но технический английский хуже. |
| **Скорость работы** | Зависит от GPU. На V100/A100 модель LLaMA 3 8B выдает от 50 до 100+ токенов в секунду (ответ генерируется мгновенно). На CPU скорость падает до 5–7 токенов в секунду (текст пишется медленнее, чем вы читаете) | Очень быстро. Задержка до первого токена (TTFT) составляет менее 0.5 сек, а скорость генерации достигает 80–100+ токенов в секунду. | YandexGPT Lite выдает до 80–100 токенов в секунду (мгновенно), а тяжелая YandexGPT Pro работает в среднем на скорости 30–50 токенов в секунду. |
| **Стоимость владения** | **Высокая CAPEX** (покупка серверов с GPU) + затраты на электричество/охлаждение. | **OPEX** ~0.01$ за 1K токенов (GPT-3.5) или $0.03 (GPT-4o). | Очень дешево для РФ-трафика, но сейчас это неактуально для Европы. |
| **Удобство деплоя** | **Сложно**. Нужно поднимать vLLM, Text-Generation-Inference. | **Мгновенно**. Просто API-ключ. | Мгновенно (API). |
| **Безопасность (Data Privacy)** | ✅ **Полный контроль**. Данные не покидают периметр. | ❌ Риск утечки. | ❌ Риск (особенно для европейской компании). |

**Вывод по LLM:** Для PoC и демонстрации можно использовать OpenAI (быстро), но для продакшена в Европе — только локальные модели.

### 3. Сравнение моделей эмбеддингов (Embeddings)

| Критерий | **Локальные (Sentence-Transformers)** <br> *Пример: all-MiniLM-L6-v2, BGE-large* | **Облачные (OpenAI)** <br> *Пример: text-embedding-ada-002 / text-embedding-3-small* |
| :--- | :--- | :--- |
| **Скорость индексации** | **CPU:** ~2-3 часа, **GPU:** ~15-20 минут | **Очень быстро**. Массовая обработка через API (пакетно) ~ 20 минут |
| **Качество поиска (Retrieval)** | **Хорошее**. BGE-large обгоняет Ada по MTEB-бенчмаркам. | **text-embedding-3-small:** Хорошее<br>**text-embedding-ada-002:** Среднее|
| **Сложность внедрения** | Средняя (нужен PyTorch, CUDA, управление памятью) | Низкая (1 строка кода, готовый API) |
| **Сложность поддержки** | Высокая (обновление драйверов, мониторинг GPU, кэширование) | Низкая (OpenAI всё чинит сам) |
| **Стоимость** | **Бесплатно** (кроме электричества). | 0.00013$ за 1K токенов (очень дешево, но за 20K документов выйдет ~ $2-5). |
| **Размерность вектора** | 384 (MiniLM) / 1024 (BGE). | 1536 (Ada) / 1536 (text-embedding-3-small). |

**Вывод по эмбеддингам:** Для MVP берем локальный `all-MiniLM-L6-v2` — он легкий, быстрый и бесплатный. Если качество поиска не устроит, перейдем на `BGE-large`.

### 4. Сравнение векторных баз данных (ChromaDB vs FAISS)

| Критерий | **FAISS** | **ChromaDB** |
| :--- | :--- | :--- |
| **Скорость поиска** | **Максимальная** (использует SIMD-инструкции, GPU-ускорение). | Медленнее FAISS (чистый Python + SQLite). |
| **Скорость индексации** | **Очень быстрая** (индекс на лету). | Умеренная (сохраняет в SQLite). |
| **Сложность внедрения** | Простой (индекс в памяти, нужно сохранять `.pkl` файлы). | Простой (есть встроенный LangChain интегратор). |
| **Удобство работы** | Нужно заботиться о сохранении состояния. | Есть постоянное хранилище (persist_directory). |
| **Стоимость владения** | **Бесплатно**. Хранится в ОЗУ сервера. | Бесплатно. Хранится на диске. |
| **Масштабируемость** | Не умеет шардироваться (один сервер). Подходит для PoC. | Тоже не умеет горизонтально масштабироваться. |

**Вывод по Vector DB:** Выбираем **FAISS**, так как он:
- Самый быстрый для поиска (критично для пользователей).
- Легко интегрируется с LangChain.
- Не требует настройки отдельной базы данных (хранится в памяти).

## Задание 6. Автоматическое ежедневное обновление базы знаний

### Источник данных

В качестве источника данных используется локальная папка `../knowledge_base`, содержащая текстовые файлы. Новые документы добавляются в эту папку вручную или через интеграцию с внешними системами.

### Скрипт обновления `update_index.py`

Скрипт выполняет:
1. Сканирование папки на наличие новых/измененных файлов
2. Проверку хешей для отслеживания изменений
3. Разбивку документов на чанки (500 токенов, overlap 50)
4. Генерацию эмбеддингов (all-MiniLM-L6-v2)
5. Обновление FAISS индекса
6. Логирование процесса

### Настройка планировщика

#### Для Windows (Task Scheduler)

```powershell
# Создание задачи
schtasks /create /tn "QuantumForge_UpdateIndex" /tr "C:\Python311\python.exe C:\project\task-6\update_index.py" /sc daily /st 06:00
```

#### Для Linux/macOS (cron)

```bash
crontab -e
# Строка:
0 6 * * * cd /path/to/task-6 && python update_index.py >> logs/cron.log 2>&1
```
